ID: BUG-002
Заголовок: Поле быстрого сообщения продавцу не имеет accessible-названия — скринридер озвучивает содержимое поля вместо его назначения
Модуль: Страница объявления — форма быстрого сообщения продавцу
Окружение: Windows 10 22H2, Chrome DevTools (Lighthouse 13.3.0, Chromium 150.0.0.0); ручная проверка через Windows Narrator (Win+Ctrl+Enter)
Шаги воспроизведения:
 1. Открыть страницу объявления https://m.avito.ru/sankt-peterburg/mebel_i_interer/stoleshnitsa_iz_massiva_dereva_na_zakaz_2169524989?context=H4sIAAAAAAAA_wE_AMD_YToyOntzOjEzOiJsb2NhbFByaW9yaXR5IjtiOjA7czoxOiJ4IjtzOjE2OiJoZExrZXVHcXFXUTRzQ2NUIjt92ah63j8AAAA.
 2. Запустить аудит Lighthouse, категория Accessibility — раздел «Names and Labels».
 3. Найти пункт «Form elements do not have associated labels» — элемент textarea (data-marker="icebreakers/textarea").
 4. Для ручной проверки: включить Windows Narrator, клавишей Tab дойти до поля быстрого сообщения.
Ожидаемый результат: Скринридер озвучивает назначение поля — например, «Текстовое поле, быстрое сообщение продавцу» — независимо от того, есть ли в поле предзаполненный текст.
Фактический результат: Элемент визуально обёрнут тегом label, но без содержательного текста, доступного скринридеру. При проверке через Narrator программа озвучила: «Поле. «Здравствуйте. Где и когда можно посмотреть?». Сканирование выкл, конец строки» — то есть вместо описания назначения поля пользователь слышит просто текст, который уже находится внутри поля (предзаполненное сообщение). Если пользователь очистит это поле перед вводом своего текста, скринридер вообще не сообщит, что это за поле и зачем оно нужно.
